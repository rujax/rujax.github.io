起因

查看图片4个通道的应用 RGBAViewer
新写了一个应用来查看图片的4个通道

在写完上篇文章之后，有几个问题一直困扰着我：

  1. 为了让应用在有缩放的屏幕上不模糊，我嵌入了 manifest.xml 文件并设置了 DPI awareness ，
    但是在屏幕分辨率发生变化时，布局无法自适应缩放，会乱掉
  2. 因为框架的限制，有些功能无法实现，比如：在原始图像的区域添加一个 打开图片 的按钮
  3. 还是因为框架的限制，能够支持的图片格式比预期要少一些
  4. 一些想要的动效无法实现

于是乎，我又翻起了之前未被我采用的方案。

Tauri

重新开始审视每个方案后，我先关注的是 Release 版本应用程序的 文件大小 。

搜索了下，AI 回答了我：

竟然跟我开始预想的不一样 (´⊙ω⊙`)

看来，还是当年 Electron 1.0 给我留下的不好印象还是太深了，
让我误以为这类使用 Web 开发作为前端的桌面应用都是体积很大的（笑

其他技术栈

通过 Tauri 官网的 快速开始 ，陆陆续续确定了其他技术栈：

  • 前端语言： TypeScript
  • 前端构建工具： Vite
  • 包管理器： pnpm
  • UI 模板： Solid
  • CSS 样式框架： Tailwind CSS
  • CSS 组件库： daisyUI

Web 前端开发需要用到的工具还是一如既往得多啊 ∑(￣□￣;)

RGBAViewer 新版本介绍

主窗口

新增加的特性：

  1. 标题栏采用由红自绿再蓝的渐变风格
  2. 图片增加 BMP/JPG/DDS/TGA 格式支持
  3. 加载原始图像增加 打开图片 按钮
  4. 右下角保存图片按钮合并为按钮组

原始图像

新增加的特性：

  • 加载原始图像后，鼠标悬浮新增 移除图片 按钮

核心功能

无变化。

结语

通过使用 Tauri 等新的技术栈重写应用，让我对于 Rust 的理解和运用更加得心应手啦 (｡･∀･)ﾉﾞ
